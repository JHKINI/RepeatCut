# RepeatCut

**기출문제를 쉽게 기록하고, 오답 데이터를 활용해 반복되는 개념과 학습 패턴을 파악하도록 돕는 학습 서비스**

RepeatCut은 기출문제를 풀면서 발생하는 오답을 문제 이미지와 함께 기록하고, 문제집·문제 번호·페이지·키워드·오답 이유를 구조화해 관리하는 웹 서비스입니다. 단순히 오답을 모아 두는 데서 끝나지 않고, 누적된 기록을 바탕으로 반복되는 개념과 개인의 오답 원인을 확인하는 것을 목표로 합니다.

## 1. 문제 정의

여러 회차의 기출문제를 공부할 때 동일하거나 유사한 핵심 개념이 여러 문제에 반복되어도, 학습자가 과거 기출을 직접 찾아 비교해야 합니다. 또한 같은 개념을 반복해서 틀리거나 비슷한 유형에서 실수하더라도 오답 이력을 누적해 자신의 패턴을 확인하기 어렵습니다.

- **사용자:** 지역농협 등 채용·자격시험의 기출문제를 반복해서 학습하는 수험생
- **기존 학습의 불편:** 오답 기록, 관련 기출 탐색, 반복 개념 및 오답 원인 파악이 각각 분리되어 있음
- **핵심 문제:** 흩어진 기출과 개인의 오답 기록이 연결되지 않아 반복 출제 개념과 반복 오답 패턴을 한눈에 파악하기 어려움
- **해결 방향:** 기출을 쉽게 기록하고, 관련 정보를 구조화해 누적 오답을 검색·분석할 수 있는 기반 마련

## 2. MVP 범위

초기 MVP는 오답을 편리하게 등록하고 관리하는 핵심 흐름에 집중했습니다.

1. 문제 이미지 업로드 및 필요한 영역 선택
2. 문제지(목록에서 선택), 문제 번호, 페이지, 키워드(자동완성), 오답 이유(목록에서 선택) 입력
3. 잘라낸 문제 이미지와 오답 정보 저장
4. 오답 목록 조회 및 키워드 검색
5. 등록한 오답 상세 확인, 수정 및 삭제
6. 기록 생성일 기준 추세 정보 조회
7. 문제지 수정·삭제, 내가 고른 답·정답 기록, 키워드·오답 이유·문제지별 통계

AI를 이용한 개념 자동 추출, 의미 기반 관련 기출 추천, 취약 개념 및 반복 오답 원인 분석은 서비스의 확장 방향입니다. 현재 구현된 CRUD·검색·추세 기능과 향후 고도화 기능을 구분해 개발하고 있습니다.

## 3. PRD 설계

PRD에서는 사용자 시나리오를 기준으로 핵심 흐름과 기능 요구사항을 구체화했습니다.

**주요 사용자 흐름**

`문제 이미지 선택 → 필요한 영역 자르기 → 오답 정보 입력 → 저장 → 목록·검색 → 상세 확인 → 수정 또는 삭제`

**핵심 요구사항**

- 문제 이미지의 필요한 부분만 선택해 기록할 수 있어야 함
- 문제집, 문제 번호, 페이지, 키워드, 오답 이유를 함께 저장해야 함
- 등록한 기록을 검색하고 최신순·오래된순으로 확인할 수 있어야 함
- 기록을 수정·삭제할 수 있어야 함
- 저장된 문제 이미지를 해당 오답 기록과 연결해 다시 조회할 수 있어야 함
- 필수 입력값과 존재하지 않는 기록 요청을 검증하고 적절히 처리해야 함

## 4. 기술 설계

### 시스템 구성

```text
React + Vite
  ├─ 이미지 선택 및 영역 지정
  ├─ 오답 등록·목록·검색·수정·삭제 UI
  └─ FastAPI에 HTTP 요청
          ↓
FastAPI
  ├─ 입력값 검증 및 API 처리
  ├─ 이미지 데이터 디코딩 및 파일 저장
  └─ SQLite 데이터 조회·등록·수정·삭제
          ↓
SQLite                    이미지 저장소 (환경변수로 선택)
  └─ 오답 메타데이터        ├─ 로컬 폴더 (기본, DB 파일 옆 uploads/)
                          └─ S3 호환 저장소 (AWS S3, Cloudflare R2 등)
```

### 기술 스택

| 영역 | 기술 | 역할 |
|---|---|---|
| Frontend | React, Vite, JavaScript | 사용자 화면과 입력·상호작용 |
| 이미지 크롭 | Pointer Events, HTML Canvas API | 드래그 좌표 계산 및 선택 영역 크롭 |
| Backend | Python, FastAPI | REST API, 입력 검증, 데이터 처리 |
| Database | SQLite (WAL), 번호로 관리하는 구조 변경(migration) | 오답 메타데이터 저장, 배포 DB 안전 업그레이드 |
| Image storage | 로컬 폴더 / S3 호환 저장소, Base64 데이터 처리 | 크롭된 이미지 파일 저장 및 조회 |
| Chart | Recharts, CSS 막대 | 기록 추세 시각화, 통계 막대 |

### 이미지 저장 흐름

1. React에서 사용자가 원본 이미지를 선택합니다.
2. Pointer Events로 드래그 시작점과 종료점을 받아 선택 영역을 계산합니다.
3. Canvas의 `drawImage()`로 원본 이미지의 해당 영역을 잘라내고 `toDataURL()`로 JPEG 데이터로 변환합니다.
4. 크롭 이미지와 오답 메타데이터를 FastAPI에 전송합니다.
5. FastAPI가 이미지 데이터를 디코딩하고, 용량(기본 5MB)과 실제 파일 형식(PNG/JPEG/WEBP)을 검사합니다.
6. 이미지 저장소에 파일을 저장한 뒤 파일명과 오답 정보를 SQLite에 기록합니다. DB 기록이 실패하면 방금 저장한 파일을 지웁니다.
7. 이미지 조회 API가 저장소 종류에 따라 파일을 직접 반환하거나 S3 주소로 이동시킵니다.

### 데이터 설계

핵심은 **문제지(`papers`)와 오답(`mistakes`)** 두 테이블이고, 나머지는 이 둘을 받쳐 주는 테이블입니다. 한 번 입력한 값을 다음부터 **선택 목록**으로 다시 고를 수 있게 문제지·키워드·시험명을 따로 두었고, 같은 값이 항상 같은 행을 가리키므로 `GROUP BY`로 바로 집계할 수 있습니다.

```text
users (회원) 1 ──< N sessions (로그인 상태)
users (회원) 1 ──< N papers (문제지정보) N >── 1 exams (시험·자격증)
                     papers 1 ──< N mistakes (오답노트) N >── 1 keywords (핵심키워드)
                                    mistakes 1 ──< N attempts (다시 푼 기록)
```

- 같은 문제지의 같은 문제 번호는 `mistakes`에 한 번만 등록합니다. 그 문제를 또 틀리면 새 줄을 만들지 않고 `attempts`에 '틀림 + 그때 고른 답 + 그때 틀린 이유'를 한 줄 더합니다. 틀린 기록은 오답 등록 화면에서만 받고, 오답 상세 화면에서는 '다시 풀어서 맞혔어요'만 기록합니다. 그래서 오답 수는 문제 수와 같고, 문제별 틀린 횟수 = 1 + 또 틀린 기록 수입니다.
- 누구의 데이터인지는 `papers.user_id` 한 곳에만 둡니다. 오답은 문제지를 통해 주인이 정해지므로 `mistakes`에는 `user_id`를 두지 않았습니다(같은 정보를 두 곳에 두면 서로 어긋날 수 있어서).
- `exams`·`keywords`는 이름만 가진 공용 목록입니다. 회원에게는 자기 문제지·오답에 쓴 것만 보여 줍니다.

**`users` — 회원** (PK: `id`)

| 필드 | 설명 |
|---|---|
| `id` | 회원의 기본 키(PK) |
| `email` | 로그인 이메일. 중복 불가(UNIQUE), 대소문자 무시 |
| `password_hash` | 비밀번호 해시(PBKDF2-SHA256 + 회원별 salt). 원문은 저장하지 않음 |
| `nickname` | 화면에 보여줄 이름 (선택) |
| `created_at` | 가입 시각 |

**`sessions` — 로그인 상태** (PK: `id` / FK: `user_id`)

| 필드 | 설명 |
|---|---|
| `id` | 기본 키(PK) |
| `user_id` | 회원 FK → `users.id` |
| `token_hash` | 로그인 토큰의 SHA-256 해시(UNIQUE). 토큰 원문은 저장하지 않음 |
| `created_at`, `expires_at` | 로그인 시각, 만료 시각(7일 뒤) |

**`exams` — 시험·자격증** (PK: `id`)

| 필드 | 설명 |
|---|---|
| `id` | 시험의 기본 키(PK) |
| `name` | 시험명. 중복 불가(UNIQUE), 대소문자 무시. 문제지 추가 화면에서 자동완성으로 재사용 |
| `created_at` | 추가 시각 |

**`papers` — 문제지정보** (PK: `id` / FK: `user_id`, `exam_id`)

| 필드 | 설명 |
|---|---|
| `id` | 문제지의 기본 키(PK) |
| `user_id` | 주인 FK → `users.id` (로그인 기능 전에 만든 데이터는 첫 회원이 가입할 때 넘겨받음) |
| `exam_id` | 시험 FK → `exams.id` (화면 기본값 `지역농협`) |
| `year` | 연도 (선택 목록) |
| `exam_type` | 시험 구분: 기출 / 모의고사 / 문제집 |
| `round` | 회차: 상반기 / 하반기 / 1~4회차 / 기타 |
| `title` | 문제지 이름 (선택). 비우면 `2025 지역농협 상반기`처럼 시험명·연도·회차로 자동 생성 |
| `total_questions` | 문항 수 (선택). 입력하면 통계에서 오답률 = 오답 수 ÷ 문항 수 계산 |
| `created_at` | 문제지 추가 시각 |

`(user_id, exam_id, year, exam_type, round, title)`은 UNIQUE라 한 회원 안에서 같은 문제지가 중복 등록되지 않습니다. (다른 회원은 같은 이름의 문제지를 따로 가질 수 있습니다)

**`keywords` — 핵심키워드** (PK: `id`)

| 필드 | 설명 |
|---|---|
| `id` | 키워드의 기본 키(PK) |
| `name` | 키워드 이름. 중복 불가(UNIQUE), 대소문자 무시. 등록 화면에서 자동완성으로 재사용 |

**`mistakes` — 오답노트** (PK: `id` / FK: `paper_id`, `keyword_id`)

| 필드 | 설명 |
|---|---|
| `id` | 오답 기록의 기본 키(PK) |
| `paper_id` | 문제지 FK → `papers.id` (오답이 달린 문제지는 삭제 불가, `ON DELETE RESTRICT`) |
| `problem_no` | 문제 번호 |
| `page` | 페이지 번호 |
| `keyword_id` | 핵심 키워드 FK → `keywords.id` |
| `reason_type` | 오답 이유 유형 (선택 목록): 개념이해부족 / 계산실수 / 문제 잘못 읽음 / 시간 부족 / 찍어서 틀림 / 기억 안 남 / 기타 |
| `memo` | 자유 서술 메모 (선택) |
| `my_answer` | 내가 고른 답 (선택, 칩 ①~⑤). 정답과 같으면 저장 불가 |
| `correct_answer` | 정답 (선택) |
| `image_no` | 이미지 식별자, 중복 방지(UNIQUE) |
| `image_path` | 저장된 이미지 파일명 |
| `created_at` | 기록 생성 시각 |

**`attempts` — 다시 푼 기록** (PK: `id` / FK: `mistake_id`)

| 필드 | 설명 |
|---|---|
| `id` | 기본 키(PK) |
| `mistake_id` | 오답 FK → `mistakes.id` (오답을 지우면 같이 삭제, `ON DELETE CASCADE`) |
| `is_correct` | 다시 풀어서 맞혔으면 1, 또 틀렸으면 0 |
| `my_answer` | 또 틀렸을 때 그때 고른 답 (선택) |
| `reason_type` | 또 틀렸을 때 그때 틀린 이유 (선택 목록) |
| `attempted_at` | 다시 푼 시각 |

- 선택 목록 중 계속 늘어나는 것(문제지, 키워드, 시험명)은 테이블 + 자동완성으로, 고정된 소수 선택지(시험 구분, 회차, 오답 이유)는 백엔드 상수 한 곳에서 관리하고 `GET /api/options`로 프론트에 내려줍니다.
- SQLite는 기본적으로 외래키를 검사하지 않기 때문에 DB 연결마다 `PRAGMA foreign_keys = ON`을 켭니다.
- DB 구조는 `PRAGMA user_version`에 번호를 적어 관리합니다(`backend/repeatcut/database.py`의 `MIGRATIONS`). 서버가 켜질 때 아직 적용 안 된 번호만 순서대로 실행하고, 번호 하나마다 한 트랜잭션이라 실패하면 그 번호는 적용 전으로 돌아갑니다. 구조를 바꾸기 전에 DB 파일을 `app.db.backup-v<이전번호>-<시각>`으로 자동 백업합니다. 서버를 여러 개 동시에 켜도 한 곳만 적용하도록 쓰기 잠금을 잡고, DB 버전이 코드보다 새로우면 데이터를 건드리지 않고 시작을 멈춥니다.
- 예전 구조(`worksheet`·`keyword`·`wrong_reason`이 문자열이던 `mistakes`)의 DB는 서버 시작 시 한 트랜잭션으로 새 구조로 옮겨지고, 원본은 `mistakes_legacy` 테이블로 남습니다.

이미지 바이너리 전체를 DB에 넣는 대신 이미지 파일은 파일 시스템에 저장하고, DB에는 파일명과 관련 메타데이터를 저장하도록 분리했습니다.

### 주요 API

| Method | Endpoint | 기능 |
|---|---|---|
| `GET` | `/api/health` | 서버 상태 확인 (DB 접속, 구조 버전, 이미지 저장소 종류) |
| `GET` | `/api/options` | 선택 목록(시험 구분·회차·오답 이유·답 번호·연도) 조회 |
| `POST` | `/api/auth/register` | 회원가입 후 바로 로그인 (토큰 반환) |
| `POST` | `/api/auth/login` | 로그인 (토큰 반환) |
| `POST` | `/api/auth/logout` | 로그아웃 (이 토큰의 로그인 상태 삭제) |
| `GET` | `/api/auth/me` | 지금 로그인한 회원 정보 |
| `GET` | `/api/exams` | 자동완성용 시험명 목록 |
| `GET` | `/api/papers` | 문제지 목록 조회 (최근에 쓴 문제지가 맨 위) |
| `POST` | `/api/papers` | 문제지 추가 (이미 있으면 기존 문제지 반환) |
| `PUT` | `/api/papers/{id}` | 문제지 수정 (같은 문제지가 있으면 409, 문항 수가 오답 수보다 적으면 400) |
| `DELETE` | `/api/papers/{id}` | 문제지 삭제 (오답이 연결돼 있으면 409) |
| `GET` | `/api/stats?paper_id=` | 키워드별·오답 이유별·키워드×이유·문제지별 오답률·답 번호 분포·다시 풀기 통계 |
| `POST` | `/api/stats/advice?paper_id=` | 통계 기반 AI 학습 추천 (Gemini, 키가 없거나 실패하면 규칙 기반) |
| `GET` | `/api/keywords` | 자동완성용 키워드 목록 (많이 쓴 순) |
| `GET` | `/api/mistakes` | 오답 목록 조회 및 키워드 검색·정렬 |
| `GET` | `/api/mistakes/trend` | 기록 추세 데이터 조회 |
| `GET` | `/api/mistakes/{id}/image` | 오답 이미지 조회 |
| `POST` | `/api/mistakes` | 오답 및 이미지 등록 (새 키워드는 자동 추가, 같은 문제지의 같은 번호가 이미 있으면 409) |
| `PUT` | `/api/mistakes/{id}` | 오답 정보 수정 |
| `DELETE` | `/api/mistakes/{id}` | 오답 기록 삭제 (안 쓰는 키워드는 정리) |
| `GET` | `/api/mistakes/{id}/attempts` | 다시 푼 기록 조회 |
| `GET` | `/api/mistakes/lookup?paper_id=&problem_no=` | 이미 등록한 문제인지 확인 (등록 화면용) |
| `POST` | `/api/mistakes/{id}/attempts` | 다시 푼 결과(맞음/틀림, 또 틀렸으면 고른 답·이유) 기록 |
| `DELETE` | `/api/mistakes/{id}/attempts/{attempt_id}` | 다시 푼 기록 삭제 |

`/api/health`, `/api/options`, 회원가입·로그인을 뺀 모든 API는 `Authorization: Bearer <토큰>` 헤더가 필요합니다(없거나 만료되면 401). 다른 회원의 문제지·오답 id로 요청하면 없는 것으로 취급해 404를 돌려줍니다.

## 5. 구현 과정

### 1) 문제 등록 UI 및 이미지 크롭

- 파일 선택 후 이미지 미리보기
- 드래그한 영역의 좌표 계산
- 화면 표시 크기와 원본 이미지 픽셀 크기를 반영해 크롭 영역 변환
- Canvas로 선택 영역을 JPEG 데이터로 생성

### 2) React–FastAPI 연동

- React에서 HTTP API를 호출해 등록·조회·수정·삭제 요청 처리
- FastAPI의 CORS 설정으로 개발 서버 간 요청 허용
- 요청·응답 상태에 따라 오류 메시지 표시

### 3) 이미지 파일과 DB 연동

- 백엔드에서 이미지 데이터 디코딩 후 파일 저장
- SQLite에 문제 메타데이터와 이미지 파일명 저장
- 이미지 조회 시 DB 기록과 실제 파일을 연결해 반환
- 삭제 시 DB 기록과 이미지 파일을 함께 정리하도록 처리

### 4) 오답 목록 관리

- 키워드 검색
- 최신순·오래된순 정렬
- 기록 상세 조회 및 수정·삭제
- 날짜별 기록 추세 데이터 조회 및 시각화

### 5) 입력 줄이기: 선택 목록 기반 등록

- 문제지는 `papers`에 한 번만 추가해 두고, 이후에는 드롭다운에서 선택합니다. 가장 최근에 쓴 문제지가 기본 선택되어, 한 문제지에서 오답을 연달아 등록할 때는 문제 번호·페이지만 입력하면 됩니다.
- 새 문제지를 추가할 때 문제지 이름을 비우면 시험명·연도·회차로 이름을 자동 생성합니다. (예: `2025 지역농협 상반기`)
- 핵심 키워드는 기존 키워드를 자동완성과 칩으로 바로 고를 수 있고, 목록에 없으면 새 키워드로 추가됩니다. 같은 개념이 `농도`, `농도 계산`처럼 흩어지는 것을 줄여 반복 개념 집계가 가능해집니다.
- 오답 이유는 유형 목록에서 고르고, 기존의 자유 서술은 메모로 남깁니다.

### 6) 문제지 관리와 정답 기록

- 문제지를 목록에서 고르고, 그 자리에서 추가·수정·삭제할 수 있습니다. 삭제는 확인 단계를 거치고, 오답이 연결된 문제지는 버튼을 막고 이유를 안내합니다.
- 예전 데이터라 연도가 비어 있는 문제지는 수정 화면에서 연도를 채웁니다.
- 내가 고른 답과 정답을 칩으로 선택 입력합니다. 같은 번호를 넣으면 저장하지 않고 안내합니다.

### 7) 통계

- 키워드별·오답 이유별 막대, 상위 키워드×오답 이유 표, 문제지별 오답률, 내가 자주 고른 오답 번호 분포를 보여줍니다.
- 문제지 단위로 걸러 볼 수 있고, 오답이 10건 미만이면 표본이 적다고 안내합니다. 문항 수가 없는 문제지는 오답률을 계산하지 않고 “문항 수 미입력”으로 표시합니다.

## 7. 배포 가이드

### 백엔드 구성

```text
backend/
  main.py                 API 라우트와 입력 검사
  repeatcut/
    settings.py           환경변수 설정
    rules.py              선택 목록·입력 한도·문제지 이름 규칙
    database.py           SQLite 연결, 번호 기반 구조 변경, 자동 백업
    repository.py         SQL 모음 (회원별 조건 user_id도 전부 여기서 건다)
    auth.py               비밀번호 해시, 로그인 토큰
    advice.py             통계 기반 학습 추천 (Gemini API, 실패하면 규칙 기반)
    image_storage.py      이미지 저장소 (로컬 / S3 호환)
    seed.py               처음 만든 DB에 넣는 예시 데이터
```

### 환경변수

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `REPEATCUT_DB` | `/workspace/data/app.db` | SQLite 파일 경로. 서버가 재시작·재배포돼도 남는 디스크(볼륨)에 둡니다 |
| `REPEATCUT_UPLOAD_DIR` | DB 파일 옆 `uploads/` | 이미지를 저장할 폴더 (`REPEATCUT_STORAGE=local`일 때) |
| `REPEATCUT_STORAGE` | `local` | 이미지 저장소: `local` 또는 `s3` |
| `REPEATCUT_S3_BUCKET` | – | S3 버킷 이름 (`s3`일 때 필수) |
| `REPEATCUT_S3_PREFIX` | `problem-images/` | 버킷 안의 폴더 |
| `REPEATCUT_S3_ENDPOINT` | – | S3 호환 서비스 주소 (Cloudflare R2, MinIO 등) |
| `REPEATCUT_S3_REGION` | – | 리전 |
| `REPEATCUT_S3_PUBLIC_BASE_URL` | – | 버킷이 공개(CDN)라면 그 주소. 없으면 1시간짜리 임시 URL로 이동시킴 |
| `REPEATCUT_S3_PRESIGN_SECONDS` | `3600` | 임시 URL 유효 시간(초) |
| `REPEATCUT_CORS_ORIGINS` | `localhost:5173/5174` | 프론트 주소 목록(쉼표 구분). 예: `https://repeatcut.example.com` |
| `REPEATCUT_MAX_IMAGE_MB` | `5` | 업로드 이미지 최대 크기 |
| `REPEATCUT_BACKUP` | `1` | `0`이면 구조 변경 전 자동 백업을 끔 |
| `VITE_API_ORIGIN` | `http://127.0.0.1:8000` | **프론트 빌드 전에** 설정하는 API 주소. 빈 값이면 같은 도메인의 `/api`로 요청 (`.env.example` 참고) |

S3를 쓰려면 `pip install boto3`를 하고, 접근 키는 `AWS_ACCESS_KEY_ID`·`AWS_SECRET_ACCESS_KEY` 환경변수로 넣습니다. 로컬에서 S3로 옮길 때는 `uploads/` 폴더의 파일을 버킷의 `REPEATCUT_S3_PREFIX` 아래로 그대로 복사하면 되고, 복사 전에도 로컬에 있는 파일은 계속 보입니다.

### 실행

```bash
pip install -r requirements.txt
cd backend && uvicorn main:app --host 0.0.0.0 --port 8000   # 프로젝트 루트에서 uvicorn backend.main:app 도 가능
npm install && npm run build                                # dist/ 를 정적 호스팅에 올림
```

서버를 여러 개(worker) 켜도 구조 변경과 예시 데이터 입력은 한 곳만 하도록 잠금을 잡습니다. SQLite는 쓰기가 한 번에 하나라서, 개인·소규모 서비스는 worker 1~2개면 충분합니다. 사용자가 늘면 PostgreSQL로 옮기는 것을 권장하며, SQL이 `repository.py`에 모여 있어 바꿀 범위가 좁습니다.

### 백업

- 구조를 바꾸는 배포 때는 DB가 자동 백업됩니다(`app.db.backup-v…`). 오래된 백업은 직접 정리하세요.
- 평소 백업은 서버가 켜져 있어도 안전한 `sqlite3 app.db ".backup 'backup.db'"`를 쓰고, 이미지 폴더(`uploads/`) 또는 버킷도 함께 보관하세요. WAL 모드라서 `app.db`만 복사하면 `-wal` 파일의 최신 내용이 빠질 수 있습니다.

### AI 학습 추천 (Gemini API)

통계 화면의 "추천 받기"를 누르면 내 통계를 Gemini에 보내 학습 방법 추천을 받습니다.

- **키 설정:** [Google AI Studio](https://aistudio.google.com/apikey)에서 API 키를 만들고, 서버를 켜기 전에 환경변수로 넣습니다. 키는 코드나 git에 넣지 않습니다.
  ```powershell
  $env:REPEATCUT_GEMINI_API_KEY = "여기에_키"
  ```
- **보내는 것:** 집계된 숫자, 키워드 이름, 오답 이유, 문제지 이름뿐입니다. 계정 정보, 문제 이미지, 메모는 보내지 않습니다.
- **안정 운영 설계:** 버튼을 눌렀을 때만 호출 / 오답 3개 미만이면 호출하지 않음 / 같은 통계는 메모리 캐시로 재사용 / 키가 없으면 규칙 기반 추천(Mock 역할) / 429·4xx·5xx·시간 초과를 구분해 규칙 기반 추천으로 대체 / AI 답은 JSON 모양을 검사한 뒤에만 사용.
- 모델 이름은 `REPEATCUT_GEMINI_MODEL`(기본 `gemini-3.8-flash`)로 바꿉니다. 모델 이름은 자주 바뀌므로, 400·404가 나면 [모델 목록](https://ai.google.dev/gemini-api/docs/models)에서 현재 이름을 확인하세요.

### 알아둘 점

- **로그인은 이메일 + 비밀번호입니다.** 로그인하면 임의의 토큰을 받고, 프론트는 요청마다 `Authorization: Bearer` 헤더로 보냅니다. 토큰은 7일 뒤 만료됩니다. 공개 인터넷에 올릴 때는 반드시 HTTPS를 쓰고, 로그인 시도 횟수 제한·이메일 인증·비밀번호 재설정은 아직 없으므로 그 전에 추가가 필요합니다.
- S3 저장소에서 이미지를 임시 URL로 넘겨줄 때(302)는 프론트가 `fetch`로 이미지를 받기 때문에 버킷에 CORS 설정이 필요합니다.
- 예전 버전은 이미지를 `public/problem-images/`에 저장했습니다. 지금도 그 폴더의 이미지는 읽기·삭제가 되지만 새 이미지는 위 업로드 폴더에 저장됩니다. 이미 git에 올라간 이미지는 `.gitignore`만으로는 빠지지 않으니, 공개 저장소라면 `git rm -r --cached public/problem-images` 후 커밋하세요. (이미 올라간 기록은 git 이력에 남아 있습니다)
- S3 저장 코드는 테스트용 가짜 클라이언트로 검증했고, 실제 버킷 연결은 배포 환경에서 한 번 확인해야 합니다.
